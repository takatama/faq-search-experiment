# FAQ育成デモ

Google Sheets: https://docs.google.com/spreadsheets/d/1x1KkOGoAUJwHjzRf5UtMb7vAX4ex7cDY2GxoE3Xu-x4/edit

## 試す順序

1. シートを開き直し、「FAQ育成」→「検索と状態を見る」を選ぶ。
2. 「保存済みの質問で試す（APIなし）」を押す。初回はGoogleの権限確認が表示される場合がある。
3. 「確認・承認」で原文と提案を読み、よいものだけH列を「承認」にする。C列とD列は修正できる。
4. 「FAQ育成」→「承認済みを公開」を選ぶ。「公開履歴」に新しい版が追加される。
5. 必要なら「前版へ戻す」で以前の検索データへ戻せる。ファイルは削除しない。

ここでの「公開」は、このデモが使う検索データの切り替えを意味する。インターネットへの一般公開ではない。

## Geminiを使う操作

自由入力の検索、検索用質問を変更したFAQの公開、フィードバックからの改善案作成に使う。Apps Scriptの「プロジェクトの設定」→「スクリプト プロパティ」にGEMINI_API_KEYを設定する。Windowsの環境変数はクラウドには引き継がれない。キーをシートのセルやソースに書かない。

使用モデルはgemini-embedding-2（768次元）とgemini-3.5-flash-lite。MAX_GEMINI_REQUESTSは1回の実行あたり既定4、設定可能範囲1〜200。検索用質問を変更しない公開はEmbeddingを再取得しない。言い換えは現状、編集用の情報として保存され、Vector検索には使わない。

フィードバックには質問と期待するFAQ IDを入力し、メニューから改善案を作る。案は必ず未確認で追加される。FAQに存在しない回答の自動作成は対象外。

## 今回の実施範囲と限界

- 公的な原文661件を登録し、20件の下準備案をGemini 1リクエストで生成した。
- 20件とも検索用質問は原文と同じだった。言い換え、識別条件、注意点を補った。検索精度がさらに上がったという結果ではない。
- 20件はすべて未確認。無修正承認率、確認時間、実環境での承認→公開→改善→再公開はまだ測っていない。
- 既存の検索精度と、この下準備機能による効果を分けて扱う。既存Holdoutの再評価は行っていない。
- 公開と切り戻しの基本処理は模擬データでテスト済み。Apps Scriptへの6ファイルの配置一致を確認済み。確認用ブラウザーは未ログインのため、メニューと実行画面の確認は未実施。
- 自動の時間トリガーは未設定。現在は人がメニューから処理を開始するデモ。
- 検索では近い候補を返す。正解が存在しない質問の判定は未検証。
- 更新処理は複数のサービスにまたがるため、途中の障害で履歴や承認欄の表示が公開ポインタとずれる可能性がある。本番化では復旧処理と権限の絞り込みを追加する。
